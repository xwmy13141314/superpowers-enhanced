# Verification Before Completion - 完成前验证技能

**当以下情况时使用此 Skill**：
- 所有开发任务完成后
- 准备交付/合并前
- 用户要求"确认完成"

## 核心原则

**证据 > 声明**

在声明"完成"之前，必须有可验证的证据。

## 触发条件

- 所有任务标记为完成
- 准备合并到主分支
- 用户要求验证完成情况

## 验证清单

### 1. 功能验证

```markdown
## 功能验证

**需求覆盖度：**
- [ ] 设计文档中所有功能点已实现
- [ ] 每个功能点有对应测试
- [ ] 所有测试通过

**验收测试：**
- [ ] 核心功能演示通过
- [ ] 边界情况测试通过
- [ ] 错误处理测试通过
```

### 2. 代码质量验证

```markdown
## 代码质量

**代码评审：**
- [ ] 无 Critical 问题
- [ ] 无 Important 问题
- [ ] Minor 问题已记录

**代码规范：**
- [ ] 遵循项目代码风格
- [ ] 命名清晰一致
- [ ] 无重复代码
- [ ] 注释适当
```

### 3. 测试验证

```markdown
## 测试覆盖

**单元测试：**
- [ ] 新增测试 N 个
- [ ] 通过率 100%
- [ ] 覆盖率 ≥ X%

**集成测试：**
- [ ] 接口测试通过
- [ ] 端到端测试通过

**回归测试：**
- [ ] 现有测试未破坏
```

### 4. 文档验证

```markdown
## 文档完整性

**技术文档：**
- [ ] API 文档已更新
- [ ] 架构文档已更新
- [ ] 部署文档已更新

**用户文档：**
- [ ] 使用说明已编写
- [ ] 变更日志已更新
```

### 5. Git 验证

```markdown
## Git 历史

**提交质量：**
- [ ] 提交信息清晰
- [ ] 每个提交有单一目的
- [ ] 无敏感信息提交

**分支状态：**
- [ ] 功能分支最新
- [ ] 与主分支冲突已解决
- [ ] 准备合并
```

## 验证报告模板

```markdown
# 完成验证报告

**项目：** [功能名称]

**验证日期：** YYYY-MM-DD

**验证人：** [Agent/人名]

---

## 验证结果

| 类别 | 状态 | 备注 |
|------|------|------|
| 功能验证 | ✅ 通过 / ❌ 未通过 | ... |
| 代码质量 | ✅ 通过 / ❌ 未通过 | ... |
| 测试覆盖 | ✅ 通过 / ❌ 未通过 | ... |
| 文档完整性 | ✅ 通过 / ❌ 未通过 | ... |
| Git 历史 | ✅ 通过 / ❌ 未通过 | ... |

## 遗留问题

| 问题 | 严重性 | 计划修复时间 |
|------|--------|-------------|
| ... | Minor | 下一版本 |

## 结论

**验证状态：** ✅ 通过 / ❌ 未通过

**建议：**
- [ ] 可以合并到主分支
- [ ] 需要修复后重新验证
- [ ] 需要额外测试

---

**签名：** __________
**日期：** __________
```

## 与 OpenClaw 集成

### 使用 exec 运行验证命令

```python
# 运行全部测试
exec(command="pytest tests/ -v --cov=src", workdir=project_path)

# 检查代码风格
exec(command="flake8 src/", workdir=project_path)

# 查看 git 状态
exec(command="git status && git log --oneline -10", workdir=project_path)
```

### 使用飞书文档记录验证

```python
feishu_create_doc(
    title="[功能名称] 完成验证报告",
    markdown=verification_report,
    folder_token="docs_folder_token"
)
```
