# Product Design - 产品设计技能

**当以下情况时使用此 Skill**：

- 完成需求分析后，需要设计产品功能
- 用户要求设计产品架构、信息架构
- 需要定义用户流程、交互逻辑
- 需要设计功能模块、页面结构
- 在 UI/UX 设计（frontend-design）之前

## 核心原则

**功能设计先行，界面设计在后**

先设计"产品做什么"（功能），再设计"产品长什么样"（界面）。产品设计关注用户需求、业务目标和技术可行性，UI/UX 设计关注视觉呈现和交互体验。

## 工作流程

### 阶段 1: 需求理解

#### 1.1 需求文档回顾

**阅读并理解：**

- 用户故事（User Stories）
- 验收标准（Acceptance Criteria）
- 业务目标（Business Goals）
- 用户痛点（User Pain Points）
- 约束条件（Constraints）

**输出：**
- 需求清单
- 优先级排序
- 成功指标

#### 1.2 用户场景分析

**定义核心场景：**

- **主要场景** - 80% 用户的使用路径
- **次要场景** - 特殊情况、边界情况
- **异常场景** - 错误处理、边界条件

**场景描述模板：**
```
场景名称：[名称]

角色：[用户角色]

目标：[用户想要达成的目标]

前置条件：[使用场景的初始状态]

触发条件：[什么触发用户行为]

主要流程：
1. 用户执行动作 A
2. 系统响应 B
3. 用户执行动作 C
...

异常流程：
- 如果 X 发生，则 Y

后置条件：[场景结束后的状态]
```

### 阶段 2: 信息架构设计

#### 2.1 功能模块划分

**将需求分解为功能模块：**

```
产品
├── 模块 1: [名称]
│   ├── 功能 1.1
│   ├── 功能 1.2
│   └── 功能 1.3
├── 模块 2: [名称]
│   └── ...
└── 模块 3: [名称]
    └── ...
```

**划分原则：**
- 高内聚、低耦合
- 单一职责
- 用户视角（非技术视角）

#### 2.2 页面/视图结构

**定义页面层级：**

```
应用
├── 公共布局
│   ├── 顶部导航
│   ├── 侧边栏
│   └── 底部
├── 主要页面
│   ├── 首页/仪表盘
│   ├── 列表页
│   ├── 详情页
│   └── 设置页
└── 模态对话框
    ├── 确认对话框
    ├── 表单对话框
    └── ...
```

**页面清单：**
- 列出所有页面/视图
- 定义页面关系
- 标注页面跳转

#### 2.3 导航设计

**导航类型：**

- **全局导航** - 主要功能入口
- **局部导航** - 当前模块内的导航
- **辅助导航** - 面包屑、返回按钮
- **关联导航** - 相关内容链接

**设计原则：**
- 清晰、一致、可预测
- 符合用户心智模型
- 移动端友好

### 阶段 3: 用户流程设计

#### 3.1 核心用户流程

**绘制主要用户路径：**

```
开始
  ↓
[登录/注册]
  ↓
[首页]
  ↓
[选择功能] ←→ [设置]
  ↓
[执行操作]
  ↓
[查看结果]
  ↓
结束
```

**流程图工具：**
- 使用文本流程图（如上）
- 或使用 Mermaid 语法
- 或在飞书白板绘制

#### 3.2 状态机设计

**定义关键状态：**

```
用户状态机：
- 未登录 → 已登录 → 已验证
- 普通用户 → VIP 用户 → 管理员

内容状态机：
- 草稿 → 审核中 → 已发布 → 已归档
- 草稿 → 已拒绝

任务状态机：
- 待处理 → 进行中 → 已完成 → 已关闭
- 进行中 → 已取消
```

#### 3.3 数据流设计

**定义数据流向：**

```
用户输入 → 表单验证 → 数据处理 → 数据存储 → 反馈展示
                ↓
            错误处理
```

### 阶段 4: 功能设计

#### 4.1 功能清单

**每个功能模块的详细设计：**

```
功能：[名称]

描述：[简要描述]

用户故事：
作为 [角色]
我想要 [功能]
以便 [价值]

验收标准：
- [ ] 标准 1
- [ ] 标准 2

输入：
- 数据项 1: [类型、格式、约束]
- 数据项 2: ...

处理：
- 步骤 1: [描述]
- 步骤 2: [描述]

输出：
- 结果 1: [描述]
- 结果 2: [描述]

异常处理：
- 异常 1: [处理方式]
- 异常 2: [处理方式]
```

#### 4.2 表单设计

**表单字段定义：**

| 字段 | 类型 | 必填 | 验证规则 | 默认值 | 说明 |
|------|------|------|----------|--------|------|
| username | text | 是 | 3-20 字符 | - | 用户名 |
| email | email | 是 | 有效邮箱 | - | 邮箱 |
| age | number | 否 | 18-120 | - | 年龄 |

#### 4.3 列表/表格设计

**列表设计：**

- 排序规则
- 筛选条件
- 分页设置
- 批量操作

**表格设计：**

- 列定义
- 列宽
- 可排序、可筛选
- 行操作

### 阶段 5: 交互逻辑设计

#### 5.1 交互规则

**定义交互行为：**

- 点击行为（链接、按钮）
- 拖拽行为
- 手势操作（移动端）
- 键盘快捷键

#### 5.2 反馈机制

**用户反馈设计：**

- 成功提示
- 错误提示
- 警告提示
- 加载状态

#### 5.3 权限控制

**角色权限矩阵：**

| 功能 | 游客 | 普通用户 | VIP 用户 | 管理员 |
|------|------|----------|----------|--------|
| 查看内容 | ✅ | ✅ | ✅ | ✅ |
| 创建内容 | ❌ | ✅ | ✅ | ✅ |
| 编辑内容 | ❌ | 自己的 | 自己的 | 所有 |
| 删除内容 | ❌ | ❌ | 自己的 | 所有 |
| 管理用户 | ❌ | ❌ | ❌ | ✅ |

### 阶段 6: 产品设计文档

**创建飞书文档，包含：**

1. **需求概述** - 简要回顾需求
2. **信息架构** - 功能模块、页面结构
3. **用户流程** - 核心流程图
4. **功能设计** - 详细功能规格
5. **交互规则** - 交互行为定义
6. **权限设计** - 角色权限矩阵
7. **非功能需求** - 性能、安全、可访问性
8. **附录** - 术语表、参考资料

## 使用方法

### 触发示例

```
用户：设计一个用户登录系统
用户：帮我规划一下产品架构
用户：这个功能的流程是什么？
用户：设计一个内容管理系统
```

### Agent 响应流程

```
1. 需求确认
   - 回顾需求文档
   - 明确设计范围

2. 信息架构设计
   - 划分功能模块
   - 定义页面结构

3. 用户流程设计
   - 绘制核心流程
   - 定义状态机

4. 功能详细设计
   - 功能清单
   - 表单/列表设计
   - 交互规则

5. 创建设计文档
   - 生成飞书文档
   - 呈现设计方案

6. 获取批准
   - 等待用户反馈
   - 迭代优化
```

## 质量标准

### 设计质量检查

完成产品设计后，必须验证：

- [ ] 需求覆盖完整性
- [ ] 信息架构清晰性
- [ ] 用户流程合理性
- [ ] 功能规格明确性
- [ ] 交互规则一致性
- [ ] 权限设计合理性

### 常见错误

❌ **避免：**
- 直接跳到 UI 设计，忽略功能设计
- 功能定义模糊、有歧义
- 忽视异常场景和错误处理
- 权限设计不完整
- 信息架构过于复杂

✅ **应该：**
- 功能先行，界面在后
- 清晰、明确的功能规格
- 考虑所有场景（正常、异常、边界）
- 完整的权限矩阵
- 简洁的信息架构
